# UI 规范：每日竞品 App Store 详情快照（竞品 Tab）

> 输入基准：`docs/UX-competitor-daily.md`（交互结构与状态契约，不在本文修改）、`docs/PRD-competitor-app-store.md`、`PRODUCT.md`。
> 视觉基线：`src/styles.css`、`src/main.ts`、`src/lib/renderResults.ts` 中的既有工作台样式。
> 页面模式：Operate。目标不是表达，而是让竞品分析、产品/研发、管理三类用户在同一页里快速确认「哪一天、哪些包、能不能看到详情、哪里不完整」。
> 本文只描述视觉与规格，不包含 HTML / CSS / 组件实现。

## 0. 视觉体系结论

### 0.1 继承原则

竞品 Tab 是现有工作台里的一个新表面，不是一次重设计。以下既有视觉决策全部保留：

| 已有决策 | 现有值 | 在竞品 Tab 的用法 |
|---|---|---|
| 页面底色 | `#f3f6fb` | 不变 |
| 内容卡片 | 白底 + `1px #dbe4f0` + `8px` 圆角 | 报告主表面、详情表面、截图/版本子面板 |
| 区块间距 | 20px（现有 `workspace-grid` 的 gap） | 全局头部与报告表面之间、详情各区块之间 |
| 间距刻度 | `--space-1..8` = 4/8/12/16/20/24/32 | 全部新组件只使用这 8 个值，不引入新的间距数字 |
| 页面宽度 | `min(1440px, 100%)`，外层留白 24px | 主列表与详情同宽，保证切换不跳 |
| 字体 | Outfit + PingFang SC 等现有字体栈 | 不引入展示字体 |
| 分段控件 | `.filter-segment` + `.filter-chip` | 日期口径、分组、状态三组切换器直接复用 |
| 状态徽标 | `.status-badge` 24px 高、999px 圆角、0.74rem/700 | 命中、未命中、失败、资产状态全部复用此尺寸 |
| 截图交互 | `.screenshots` + `.screenshot-trigger` + `.screenshot-lightbox` | 保留视觉与放大层，只把详情页的排列从横滑改为响应式网格 |
| 版本历史 | `.version-history`（`details/summary`、`+/-`、左侧 2px 蓝线） | 直接复用，默认展开 |
| 事实列表 | `.info-list` + `.info-row` | 详情页快照事实、源数据、App Store 元数据复用 |
| 焦点环 | `2px #93c5fd`，`offset 2px` | 全站一致 |

### 0.3 五条视觉原则

1. **红色只留给失败。** 请求失败、抓取失败用红；`bundle_not_found` 是诚实的查询结果，用中性灰 + 虚线；资产缺失用琥珀色。三者不能混用。
2. **颜色永远配文字和形状。** 命中是实心绿 +「命中」；未命中是虚线灰 +「App Store 未命中」+ 虚线问号图标；部分资产是琥珀描边 + 半填充图标。
3. **汇总层与条目层分开表达。** 汇总卡的「未命中」用琥珀色提示关注比例；单条未命中行用中性色说明查询结果。同一事实，不同语境，不同语气。
4. **密度优先，动效退后。** 竞品行 64px 高、组头 56px、截图网格 12px 间距。动效只用于展开、悬停、图片淡入，不做页面入场编排。
5. **不制造第二套控件语言。** 分段、徽标、截图卡、版本面板、事实列表全部复用现有工作台的形状与尺寸。

## 1. 布局与栅格

### 1.1 全局框架

沿用现有 `app-shell` → `workspace-frame` 结构，不新开页面级布局。

| 项 | 桌面（≥ 1200） | 平板（841–1199） | 窄屏（≤ 840） |
|---|---|---|---|
| 页面外边距 | 24px（`--space-6`） | 24px | 16px（`--space-4`，沿用现有 840 断点） |
| 内容最大宽度 | 1440px | 100% | 100% |
| 全局头部与内容间距 | 20px | 20px | 20px |
| 内容区块纵向间距 | 20px | 20px | 16px |
| 卡片内边距 | 20px | 20px | 16px（沿用现有 840 断点） |

**12 列心智栅格**（不引入新的栅格库，只作为对齐依据）：

- 内容宽度按 12 列理解，列间距 20px；汇总卡占 3 列 × 4，详情双栏为 7 + 5 或 6 + 6。
- 所有区块左边缘对齐到内容卡片内边距（20px）；行内图标、文字、右侧状态形成稳定的三列节奏。
- 576px 以下不做移动端完整承诺，但查看与下钻必须可用。

### 1.2 竞品 Tab 主列表页

主列表是**一个连续的白色报告表面**（`.report-surface`），内部用背景带和分隔线分区。不要在每组外套一层新卡片，避免「卡片里套卡片」削弱扫描节奏。

```text
report-surface（白底 / 1px #dbe4f0 / 8px 圆角）
├─ A 标题区             padding 20 / 20 / 12
├─ B 批次条             正常态并入 A 右侧；异常态为 A 下方的整宽提示条
├─ C 控制条             padding 12 / 20 / 14，浅蓝底，上下 1px 分隔
├─ D 汇总卡             padding 20，4 列，间距 12
├─ E 分组列表
│   ├─ 列表头            padding 12 / 20，底部 1px 分隔
│   ├─ 组头              高 56，padding 10 / 16，浅灰底
│   ├─ 命中行 × N        高 64，padding 12 / 16，行间 1px #f1f5f9
│   ├─ 未命中子区标题    高 32，padding 8 / 16，浅灰底，上下分隔
│   └─ 未命中行 × N      高 64，同上
└─ F 页脚               padding 16 / 20，浅灰底，顶部 1px 分隔
```

**纵向节奏表**（从上一个元素的下边缘到下一个元素的上边缘）：

| 位置 | 间距 | 说明 |
|---|---|---|
| 页面标题 → 日期行 | 4px | 标题与日期是一个整体 |
| 日期行 → 控制条 | 12px | 先确认「看哪天」，再操作 |
| 控制条 → 汇总卡 | 20px | 操作与结果分段 |
| 汇总卡 → 列表头 | 24px | 总量与明细分段 |
| 列表头 → 第一组 | 0 | 用 1px 分隔线，不再加空隙 |
| 组头 → 第一行 | 0 | 组头自身有浅灰底，形成边界 |
| 命中行 → 未命中子区 | 0 | 用子区标题的整宽浅灰带断开 |
| 组与组之间 | 0 | 下一组组头顶部 1px `#dbe4f0`，比行分隔更重 |
| 列表 → 页脚 | 0 | 页脚浅灰底 + 1px 分隔 |

**列结构**：

- 竞品行：`40px 图标 | minmax(0, 1fr) 文字 | auto 右侧状态/日期/箭头`，列间距 12px。
- 组头：`16px 展开箭头 | minmax(0, 1fr) 组名与计数 | auto 时间线`。
- 列表头：左侧说明文字，右侧两个文字操作，`space-between`。

### 1.3 竞品详情页

详情页与主列表共用外层宽度，不缩窄成阅读页。原因是截图网格与双栏事实需要横向空间。

```text
breadcrumb + 返回             高 32（可点击区域 44），下方 12
identity-surface              白卡，padding 20，图标 80 + 文字 + 右侧状态/链接
         ↕ 16
context-strip                 浅蓝底，padding 12 / 16，8px 圆角
         ↕ 20
facts（约 7 列）  ↔ 24px ↔  version-history（约 5 列）
         ↕ 24 + 1px 分隔
截图区                        标题行 + 12px + 响应式网格
         ↕ 24 + 1px 分隔
metadata 两栏（源数据 / App Store），栏间距 24
```

| 区块 | 桌面尺寸 | 窄屏行为 |
|---|---|---|
| 面包屑 / 返回 | 32px 高文字行；返回按钮点击区 44px | 保持一行，必要时省略中间层级 |
| 身份头 | 80px 图标 + 24px 间距 + 文字；右侧状态徽标 28px | 图标 64px；状态移到名称下方 |
| 快照上下文条 | 最小 64px，padding 12/16 | 单列；包切换器移到下一行 |
| 事实 / 版本双栏 | 7 : 5，间距 24px | ≤ 959 单列，版本面板在事实之后 |
| 截图网格 | 列宽 160–200px，间距 12px | 自动降为 3 / 2 列 |
| 元数据 | 两等栏，间距 24px | ≤ 640 单列 |

### 1.4 响应式断点

沿用现有 840px 与 960px 断点，新增 641–959 的 2×2 汇总规则。

| 宽度 | 全局头部 | 控制条 | 汇总卡 | 组头 | 详情 |
|---|---|---|---|---|---|
| ≥ 1200 | 品牌 / Tab / 区域说明同一行 | 两行：日期+口径、分组+状态 | 4 列 | 名称与计数一行，时间线右下 | 双栏 |
| 960–1199 | 同上 | 两行，允许换行 | 4 列 | 同上 | 双栏 |
| 841–959 | 同上 | 两行，簇内可换行 | 2 × 2 | 时间线移到计数下一行 | 单列 |
| 641–840 | 品牌与区域一行，Tab 第二行 | 每个簇一行，标签在上 | 2 × 2 | 时间线整宽另起 | 单列，图标 64 |
| ≤ 640 | 同上，Tab 可横向滚动 | 单列堆叠，控件可换行 | 2 × 2 | 计数换行 | 单列，截图 2 列 |

## 2. 组件样式规格

### 2.1 全局 Tab 导航与区域说明

- **位置**：全局头部内，品牌之后、区域说明之前；与「App Store 搜索」「竞品」同级。
- **尺寸**：每个 Tab 高 44px，左右内边距 16px，字号 0.9rem / 600，Tab 间距 4px。
- **默认**：文字 `#475569`，透明底，无边框。
- **选中**：文字 `#1d4ed8`，底部 2px `#2563eb` 实线；不加背景块。直接复用现有 `.canvas-tab` 的视觉语言。
- **悬停**：底 `#f8fafc`，文字 `#334155`。
- **焦点**：2px `#93c5fd` 环，offset 2px。
- **窄屏**：≤ 840 时 Tab 独占第二行，高度 44px；超出宽度横向滚动，不换行、不收缩字号。
- **区域说明**：竞品 Tab 下隐藏国家选择器与国家标记，右侧改为静态文字「8 个区域自动抓取 · 不可筛选」，字号 0.82rem / 500，颜色 `#475569`。不加边框、不加胶囊，避免看起来可点击。

### 2.2 页面标题区

- **主标题**：`竞品日报`，20px / 700（1.25rem），行高 1.2，颜色 `#0f172a`。语义上是本页唯一 H1，但视觉上小于全局品牌名（现有 1.5rem），避免两个同级大标题互相竞争。
- **日期行**：0.88rem / 500，颜色 `#475569`，与标题间距 4px。格式 `2026-11-18（昨日）· UTC 目标日期 · 投放口径`。
  - 「昨日」仅在日期等于昨天时出现；其他日期显示 `2026-11-15`，不加括注。
  - 口径用文字后缀，不只靠上方切换器表达。口径变化时，这一行必须同步。
- **右侧批次摘要**：0.76rem / 500，`#475569`，右对齐；正常态为「● 批次正常 · 更新于 11-19 09:31 · 范围完整」。绿点 8px，`#16a34a`。
- **「回到昨天」**：仅当日期不是昨天时出现在控制条日期簇内；文字 0.8rem / 600，`#1d4ed8`，高 28px，无背景；悬停加深为 `#1e40af`。

### 2.3 批次可信度条

**正常态**

- 不单独占一行，作为标题区右侧的摘要文字。
- 8px 实心圆点 `#16a34a` + 文字，行高 1.5，允许换行；与标题区底边距 12px。
- 无边框、无背景，尽量后退。

**异常态（`range_complete = false` / `stale = true`）**

- 位于标题区下方、控制条上方，整宽；最小高度 40px，padding 10px 12px，圆角 8px。
- 琥珀态：底 `#fffbeb`，边框 1px `#fde68a`，图标与文字 `#92400e`。
- 红色态只用于批次请求失败：底 `#fef2f2`，边框 1px `#fecaca`，文字 `#b91c1c`。
- 结构：16px 线性图标（警示三角 / 错误圆叉）+ 说明文字 0.82rem + 可选文字链接「查看批次记录」。
- 文案：
  - 范围不完整：「本日源数据可能缺少部分包，计数仅供参考。」
  - 过期：「该批次已被标记为过期，详情可能不是最新。」
  - 两者同时出现时合并为一条，用「；」连接，不堆叠两条。
- 不阻塞浏览，不遮挡汇总卡，不改变后续区块的背景。

**无批次**

- 不显示此条，直接进入「这一天还没有快照」空态。

### 2.4 控制条

**容器**

- 整宽，padding 12px 20px 14px，背景使用现有 `.filter-bar` 的浅色渐变（白 → `#f8fbff`），上下各 1px `#e2e8f0` 分隔。
- 桌面两行，行间距 10px；每行左右两组，`space-between`。窄屏每簇独占一行，标签在上、控件在下，簇间距 12px。
- 控件统一高度 34px；日期箭头与图标按钮 30×30px；所有控件圆角 8px。

**分组与标签**

- 标签：0.72rem / 700，字距 0.02em，`#64748b`；桌面与控件同一基线，标签右侧 8px。
- 四组：日期、口径、分组、状态。顺序不可变。

**日期控件**

- 结构：`[‹] [2026-11-18 ▾] [›]`，外加可选的「回到昨天」。
- 左右箭头：30×30px，白底，1px `#d7e1ed`，图标 14px，`#475569`；悬停底 `#f8fafc`，边框 `#cbdaf0`。
- 日期按钮：最小宽 132px，高 34px，白底，1px `#d7e1ed`，文字 0.82rem / 600，`font-variant-numeric: tabular-nums`，左侧日历图标 14px `#64748b`。
- 最大可选日期为昨天；未来日期禁用，disabled 透明度 0.45，不可聚焦。
- 加载中控件保持可用；日期按钮右侧出现 0.72rem「更新中」文字，不使用全屏 spinner。

**日期口径切换器（投放 / 上架）**

- 二选一分段，直接复用 `.filter-segment`：容器 4px 内边距，1px `#dbe4f0`，圆角 10px，背景 `#f8fbff`。
- 每个选项高 34px，左右 12px，0.82rem / 600。
- 未选中：透明底，`#64748b`。
- 选中：白底，1px `#dbeafe`，文字 `#0f172a`，700，带 `--shadow-control`。选中不能只靠颜色，字重 + 抬起的白色块共同表达。
- 文案固定「投放日期」「上架日期」；不使用「首投」「上架」缩写，避免与首次上架混淆。
- 切换时只刷新列表区，控件本身立即切换选中态，不等接口返回。

**分组切换器（团队 / 类目 / iOS 版本）**

- 三选一，视觉完全同口径切换器，宽度自适应文字。
- 默认「团队」；切换后所有组重新展开（与 UX 一致）。
- 选中态同样白底 + 加粗 + 阴影。

**状态切换器（全部 / 命中 / 未命中）**

- 三选一，视觉同口径切换器。
- 计数放在文字后：`未命中 6`。计数是 18px 高的胶囊，0.72rem / 700；未命中计数底 `#fef3c7`、字 `#92400e`；命中计数底 `#dcfce7`、字 `#166534`。
- 选中时计数胶囊保持自身颜色，不被白底吞掉，保证「今天有多少未命中」始终可读。
- 筛选生效时，列表头上方出现一行「当前为筛选结果 · 仅看未命中 · 6 包 / 当日共 42 包」，0.78rem，`#475569`，右侧「清除筛选」文字链接。

**控制条状态矩阵**

| 状态 | 表现 |

### 3.2 使用规则

1. **红只给失败。** `bundle_not_found`、过期、范围不完整、资产缺失都不用红。红只用于 HTTP 失败、超时、解析失败、详情请求失败。
2. **未命中永远是「中性灰 + 虚线 + 文字」。** 不能只靠灰色文字，必须有徽标和虚线占位图标。
3. **汇总层与条目层分工。**
   - 汇总卡「未命中」：琥珀数字 + 琥珀比例胶囊，提示比例需要关注。
   - 组头「未命中」：数字琥珀，标签仍为 `#475569`。
   - 未命中行徽标：中性灰虚线，说明查询结果，不制造错误感。
4. **资产状态是琥珀，不是红。** 图片缺失影响「看长相」，但不代表页面坏了；用琥珀 + 具体数量，不阻塞版本历史与文字。
5. **过期不等于失败。** `stale` 用琥珀提示条，保留全部内容可读。
6. **任何状态都不能只靠颜色。** 徽标有文字，图标有形状差异（实心 / 虚线 / 半填充 / 空），时间线当前日有描边，选中分段有字重和白色块。
7. **悬停不改变语义色。** 绿色徽标悬停仍是绿色；未命中徽标悬停仍是灰色虚线。
8. **焦点环统一。** `2px #93c5fd`，offset 2px；深色放大层内焦点环改为白色 2px，保证可见。
9. **对比度。** 上述文字与浅底组合均达到 4.5:1 以上；不把 `#64748b` 放在 `#f1f5f9` 上作为状态文字。

### 3.3 加载态

- **结构骨架，不用居中 spinner。** 骨架块颜色 `#eef2f7`，高光 `#f8fafc`，1.4s 线性循环；圆角 8px。
- 主列表加载：
  - 标题保持真实日期与口径；
  - 控制条保持可用；
  - 汇总区 4 个 88px 高骨架；
  - 列表区显示 3 组：每组 56px 组头骨架 + 3 个 64px 行骨架。
- 骨架必须带文字「正在加载 2026-11-18…」，不仅靠动画。`aria-busy="true"`，完成后 `aria-live="polite"` 播报「已加载，共 N 个包」。
- 加载新日期时清空旧数字，不保留变暗的旧值，防止把旧数据误读为新日期。
- 详情加载：身份头 + 上下文条骨架，事实/版本/截图区域各自骨架；包切换器保持可用。
- `prefers-reduced-motion: reduce` 时动画停止，保留静态骨架与文字。

### 3.4 空态

空态分三级，视觉强度依次降低。

| 场景 | 容器 | 尺寸 | 标题 | 说明 | 操作 |
|---|---|---|---|---|---|
| 某天无快照 | 页面级空态卡 | 最小 240px，padding 36 / 28，margin 18 | 1.25rem / 700 | 0.86rem `#475569`，说明每日 09:30 抓取 | 主：`回到昨天`；次：`查看最近有数据的日期` |
| 有批次但当日无包 | 页面级空态卡 | 同上 | `当天没有符合条件的 iOS 竞品包` | 列出当前口径与过滤规则 | 次：`切到上架日期口径`、`查看前一天` |
| 筛选无结果 | 列表内联卡 | 最小 160px，padding 28 / 24 | 1.05rem / 700 | `当日 42 个包全部命中了 App Store。` 0.82rem | 次：`清除筛选` |

- 页面级空态复用现有 `.empty-state` 的边框、留白和 40px 状态标记；但标题固定 1.25rem，不使用现有 `clamp(1.4rem, 2vw, 1.85rem)`，避免在工作台内过大。
- 内联空态不显示 40px 状态标记，只用标题 + 说明 + 一个文字按钮，保持安静。
- 某天无快照时**不显示汇总卡、不显示空分组、不显示批次条**；避免「0 个包」被误读成业务结论。
- 未命中详情中的「无截图 / 无版本」不是页面空态，是内容缺失块：虚线边框、0.82rem `#64748b`、居中，最小高度 120px，可带一个次要操作。

### 3.5 错误态

- **整页报告失败**：保留标题、日期、批次条、控制条；汇总与列表区域替换为错误卡。
  - 错误卡：白底、1px `#e2e8f0`、圆角 8px、最小高度 240px、居中、padding 36 / 28。
  - 14px 错误圆叉 `#b91c1c`；标题 `报告加载失败` 1.05rem / 700 `#0f172a`；原因 0.82rem `#475569`；主按钮 `重试` 36px；次按钮 `回到昨天`。
  - 不使用整块红底，红色只出现在图标和少量关键字。
- **局部失败**：只替换失败区块，其他区块保留。区块错误：最小高度 120px，标题 0.92rem / 700，说明 0.8rem，`重试` 文字按钮。
- **详情失败**：错误卡显示「无法加载该竞品详情」+ 具体包与日期 + `重试` / `返回列表`。
- **单图失败**：保留卡片尺寸与圆角，底 `#fef2f2`，边框 1px dashed `#fecaca`，图标 16px `#b91c1c`，文字「截图加载失败」0.78rem，`重试` 文字按钮 0.76rem；不阻断其他截图和版本历史。
- **错误文案必须带对象**：「无法获取 2026-11-18 的竞品快照」，而不是空泛的「出错了」。

### 3.6 部分数据

- 批次不完整 / 过期：琥珀提示条常驻在数据上方，**不阻塞**；汇总数字照常显示，但旁边保留提示。
- 单包详情不完整：事实区对应值显示 `—`，并在该行右侧显示 18px 高「详情不完整」小徽标；不把整页降级。
- 资产部分缺失：截图标题行右侧显示「图片部分缺失」；缺失的卡片用占位块，其余正常显示。
- 部分失败与整体失败必须在文案和颜色上区分：琥珀 = 数据不完整，红 = 请求失败。

**占位规则**

- 命中但图标加载失败：显示 App 名称首字母占位 + 琥珀小点，表示「有这个 App，只是图标没抓到」。不能显示问号，否则会和未命中混淆。
- 未命中：虚线问号占位，永远不显示首字母，因为源展示名不是 App 身份。
- 图标不允许拉伸；`object-fit: cover`，圆角裁切。

### 4.2 截图尺寸表

| 场景 | 宽度 | 比例 / 高度 | 圆角 | 间距 |
|---|---|---|---|---|
| 详情网格卡 | 160–200px（随列宽） | 1290 / 2796，约 2.167 倍宽 | 18px | 12px |
| 放大层 | 高度 `min(100%, 720px)`，宽度按比例 | 1290 / 2796 | 12px | 12px |
| 图片缺失占位 | 与网格卡一致 | 与网格卡一致 | 18px | 与网格一致 |

- 缩略图最小宽度不低于 160px，避免截图内容不可辨；最大不超过 200px，避免单张过大破坏网格节奏。
- 不使用固定高度；必须按比例计算，防止截图被裁切或压扁。
- 首屏前 3 张使用 eager，其余 `loading="lazy"` + `decoding="async"`；始终提供宽高或比例，避免布局位移。

### 4.3 懒加载占位

- 占位底色 `#e2e8f0`，与现有截图卡背景一致；可叠加 1.4s 的浅色扫光，但 `prefers-reduced-motion` 时静止。
- 图片加载完成：180ms 淡入（透明度 0 → 1），占位不跳动。
- 图片加载失败：占位切换为红色虚线 + 错误图标 + 「截图加载失败」+ `重试`；卡片尺寸保持不变。
- 不在加载时显示文件名、URL 或大面积文字；截图本身是内容。
- 首屏截图不显示 spinner，只显示占位底色；失败后才出现文字。

### 4.4 点击放大

- 复用现有 `.screenshot-lightbox`：
  - 全屏固定层，底 `rgba(15, 23, 42, 0.88)`；
  - 顶部右侧关闭按钮，38px 高，白色文字，半透明深底；
  - 底部左侧说明、右侧计数 `3 / 6`；
  - 图片高度 `min(100%, 720px)`，比例 1290 / 2796，圆角 12px；`object-fit: contain`；
  - 打开时锁定页面滚动。
- 从被点击的那张开始，可横向滚动 / 键盘左右切换；不自动播放。
- `Esc` 关闭，关闭后焦点回到触发缩略图；打开时焦点进入关闭按钮或当前图。
- 放大层内图片失败：显示红色占位与「图片加载失败」，不关闭放大层。
- 打开/关闭 180ms 淡入淡出；`prefers-reduced-motion` 时无过渡。
- 未命中详情不提供放大入口；缺失图不提供放大入口。
