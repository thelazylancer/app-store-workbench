# UX：每日竞品 App Store 详情快照（竞品 Tab）

> 依据：`docs/PRD-competitor-app-store.md`（6.2 / 8. WWA-006）、`PRODUCT.md`。
> 范围：只设计交互、信息层级与低保真线框，不包含 HTML / CSS / 组件实现。
> 页面模式：Operate（内部工作台，用户来完成任务；清晰、可扫描、可回溯优先于表现力）。

---

## 0. 设计前提与术语

### 0.1 已拍板约束（不在本文重新讨论）

- 页面不提供国家筛选；国家仅作为后端抓取范围。
- 默认展示昨天的数据。
- 日期口径可在「投放日期 `first_ad_date`」与「上架日期 `listing_date`」之间切换。
- 分组维度：团队（默认）/ 类目 / iOS 版本。
- 主列表按竞品 / 团队聚合：包数量、命中数、未命中数、近 7 天时间线。
- 点击竞品进入详情页：该竞品全部包、图标、截图缩略图、版本历史。
- App Store 未命中（`bundle_not_found`）的包有独立、明确的状态展示。
- 新页面是工作台新增的「竞品」Tab，与现有「App Store 搜索」Tab 并列。

### 0.2 两个关键模型

**「竞品」是什么**

- 命中包：以 `appleId` 聚合为一个竞品行；通常 1 个包，少数情况下同一 App 有多个 `package_code`，此时该行显示「N 个包」。
- 未命中包：没有 App Store 身份，一个 `package_code` 就是一个独立竞品行，显示源 `display_name` 和 `package_code`。

**三层聚合**

```text
日期快照（所选日期 + 日期口径）
  └─ 分组（团队 / 类目 / iOS 版本）      ← 组头显示包数、命中、未命中、近 7 天
       └─ 竞品（appleId 或单个未命中包）  ← 行显示图标、真实名称、状态
            └─ 包（package_code）        ← 仅详情页出现；多包时用包切换器
```

计数规则：

- 组头的「包数量 / 命中数 / 未命中数」始终按 **包** 计数，不按竞品计数。
- 竞品数作为组头的次级信息，回答「这一组有几个 App」。
- 同一 App 的多个包如果分属不同团队，会同时出现在两个团队组中；这是分组维度的正常结果，组内计数各自按包计算。

### 0.3 状态词汇

| 内部值 | 页面文案 | 含义 |
|---|---|---|
| `lookup_status = matched` | `App Store 已命中`（行内简写「命中」） | Bundle ID 在至少 1 个抓取区域精确匹配 |
| `lookup_status = bundle_not_found` | `App Store 未命中` | 8 个区域均未找到精确匹配；不是系统失败 |
| `enrich_status` 非完整 | `详情不完整` | 命中但商品页字段缺失 |
| `asset_status = partial / failed` | `图片部分缺失` / `图片缺失` | 本地图片未全部保存 |
| `range_complete = false` | `数据范围可能不完整` | 当日源数据批次不完整 |
| `stale = true` | `数据已过期` | 批次被标记为过期 |

「未命中」不得使用「失败」「错误」措辞：它是诚实的查询结果，不是系统异常。「失败」只用于请求或抓取异常。

## 1. 页面结构

### 1.1 全局框架与 Tab 切换

现有工作台是单页应用：顶部是 Logo + 标题、商店国家标记，主体是搜索编排区 + 结果区。新增「竞品」Tab 后：

```text
全局头部
  [Logo] App搜索工作台      [ App Store 搜索 ] [ 竞品 ]        US 区 / 8 区域抓取
─────────────────────────────────────────────────────────────────────────────
当前 Tab 的内容
```

规则：

- Tab 放在全局头部，作为同级主导航；「竞品」为默认选中的新 Tab 时，浏览器标题可保持工作台名称，页面内标题用「竞品日报」。
- **进入「竞品」Tab 后隐藏国家选择器与国家标记**，改为静态说明「8 个区域自动抓取 · 不可筛选」。避免用户把搜索 Tab 的国家选择误认为竞品报告也受影响。
- 两个 Tab 各自保留自己的状态；从竞品详情跳到搜索 Tab 时只预填 Bundle ID，不自动发起搜索。
- 竞品 Tab 内部有两个视图：**竞品日报（主列表）** 与 **竞品详情**。详情不是独立 Tab，是从列表下钻的页面，顶部提供返回。

### 1.2 竞品报告主列表页

从上到下分为 6 个区块：

| 区块 | 作用 | 是否随筛选变化 |
|---|---|---|
| A. 页面标题 + 快照日期 | 确认「我在看哪一天」 | 日期变化 |
| B. 批次可信度条 | 批次是否完整 / 过期 / 更新时间 | 日期变化 |
| C. 控制条 | 日期、日期口径、分组、命中状态 | 用户操作 |
| D. 汇总卡 | 当日包总数、竞品数、命中、未命中 | 仅日期 / 口径变化，不受状态筛选影响 |
| E. 分组列表 | 组头 + 竞品行 + 未命中子区 | 分组 / 状态筛选变化 |
| F. 页脚说明 | 数据口径、过滤规则、快照限制 | 固定 |

区块细节：

**A. 标题区**

- 主标题「竞品日报」。
- 日期行：「2026-11-18（昨日）」+ 小字「UTC 目标日期」。
- 若当前日期不是昨天，显示「回到昨天」快捷入口（同时出现在控制条，二选一即可；建议放在日期控件旁）。
- 不出现国家筛选或区域切换。

**B. 批次可信度条**

- 正常：单行浅色状态「批次正常 · 更新于 11-19 09:31 · 范围完整」。
- 异常：升级为横向提示条，说明问题与影响范围，但不阻塞浏览。
  - `数据范围可能不完整`：提示「本日源数据可能缺少部分包，计数仅供参考」。
  - `数据已过期`：提示「该批次已被标记为过期，详情可能不是最新」。
- 无批次时不显示此条，直接进入「某天无数据」态。

**C. 控制条**

顺序（桌面一行，窄屏两行）：

```text
日期 [‹] [2026-11-18 ▾] [›] [回到昨天]     口径 [投放日期 | 上架日期]
分组 [团队 | 类目 | iOS 版本]               状态 [全部 | 命中 | 未命中]
```

- 日期控件：前一天 / 后一天箭头 + 日期选择；最大可选日期为昨天，不允许未来日期。
- 口径为二选一分段控件，默认「投放日期」。
- 分组为三选一分段控件，默认「团队」。
- 状态为三选一分段控件，默认「全部」；「未命中」上显示当日未命中包数。
- 每次变更只刷新列表区，控制条本身保持可用；刷新期间列表显示骨架，不整页闪烁。
- 筛选条件写入 URL，刷新页面或从详情返回时保持。

**D. 汇总卡**

四张卡，横向排列：

1. 包总数（当日符合口径的包）
2. 竞品数（聚合后的 App 数，含未命中包）
3. 命中（数量 + 占包总数比例）
4. 未命中（数量 + 占包总数比例，使用警示色，但不使用「错误」语义）

说明：汇总卡始终展示**当日全量**，不随「命中 / 未命中」筛选变化；筛选状态在列表区用文字说明。这样用户不会误以为当天总量变少。

**E. 分组列表**

列表头：`团队 · 按包数排序`（随分组维度变化） + `[全部展开] [全部收起]`。

每个分组是一个可折叠区块：

- 组头（整行可点击，展开/收起）：
  - 组名（团队名 / 类目名 / 「最低 iOS 15.0」；缺失值显示「未分类」「未知 iOS 版本」）。
  - `N 包 · H 命中 · M 未命中`。
  - 次级 `X 个竞品`。
  - 近 7 天迷你时间线（7 根柱，当前日高亮；悬停/聚焦显示「11-12 · 8 包」；点击有批次的柱子跳转到该日期）。
- 组体：
  - 命中竞品行：图标、真实 App 名称、`package_code`、状态、当前口径日期、类目、最低 iOS、包数（多包时）、截图数。行尾有进入详情的方向指示。
  - 未命中子区：组内固定放在命中行之后，标题「App Store 未命中 · N 个包」，用分隔线和浅底色与命中行区分。每行显示占位图标、源 `display_name`、`package_code`、「App Store 未命中」徽标、当前口径日期。
  - 若某组没有命中包，未命中子区仍然显示，组头命中数为 0；不允许把整组隐藏。
- 默认全部展开；用户手动收起后，在本次会话内保持。切换日期时保留仍存在的组展开状态；切换分组维度时重新全部展开。
- 排序：组按包数降序，同数量按组名；命中行按 App 名称；未命中行按 `package_code`。

**F. 页脚说明**

一行小字，解释数据边界：

- 「数据来源：内部首投包接口 + App Store 精确 Bundle ID 匹配；仅含 iOS 包。」
- 「版本历史为当日商品页可见快照，不是 App Store 全量历史。」
- 「页面不提供国家筛选；命中国家/区域仅作抓取记录。」

### 1.3 竞品详情页

详情页是主列表的下钻，顶部保留来源上下文。区块：

| 区块 | 内容 |
|---|---|
| A. 返回与面包屑 | 竞品日报 / 团队 A / Begla；返回按钮 |
| B. 身份头 | 大图标、真实名称（未命中时为源展示名）、包标识、团队、状态徽标、App Store 链接 |
| C. 快照上下文条 | 快照日期、日期口径、为什么出现在当天列表 |
| D. 包切换器（仅多包时出现） | 每个 `package_code` 一个可选项，带命中状态 |
| E. 当日快照事实 | 投放/上架/首百/下架日期、类目、最低 iOS、当前版本、抓取时间、命中区域（静态） |
| F. 截图区 | 缩略图横向排列，点击打开放大层；图片缺失时显示占位与来源说明 |
| G. 版本历史 | 当日可见版本列表：版本号、发布时间、更新说明（可展开） |
| H. 源数据 / App Store 元数据 | 源展示名、`package_code`、`appleId`、价格、评分、URL |

规则：

- 详情只读取 URL 中的日期与日期口径，**不提供独立的口径切换控件**；顶部明确显示继承来的口径，返回列表时保持原状态。这保证「切换口径后列表和详情一致」。
- 若竞品有多个包，D 区出现包切换器；E/F/G 始终跟随当前选中的包（资产与版本按 `package_code` 存储，不能把多个包的截图和版本混在一起）。只有一个包时，D 区退化为一行「包：com.x.y」。
- 快照上下文条写清楚入选原因，例如「因投放日期 = 2026-11-18 出现在当日列表」；上架口径则替换为「因上架日期 = …」。
- 若接口返回的 `fetched_at` 与所选快照日期不一致，在 C 区下方显示提示条「该包记录更新于 X，可能不是所选日期的原始快照」。不隐藏这种不一致。
- 未命中详情不是空白页：保留身份头、快照事实和「为什么未命中」说明，隐藏截图与版本历史，替换为说明块。

### 1.4 页面状态与状态契约

用 URL 表达可分享、可返回的状态（不写实现）：

```text
?tab=competitor
&date=YYYY-MM-DD          # 默认昨天（UTC 目标日期）
&date_kind=first_ad       # first_ad | listing，默认 first_ad
&group_by=team            # team | category | ios_version，默认 team
&status=all               # all | hit | miss，默认 all
&view=detail              # 主列表省略
&competitor=<key>         # 命中用 apple:<appleId>；未命中用 pkg:<packageCode>
&package=<packageCode>    # 详情中当前选中的包
```

- 返回列表使用浏览器历史或等价机制，恢复滚动位置与分组展开状态。
- 跨会话不记忆筛选偏好；默认口径和默认分组每次进入保持 PRD 约定，避免「上次筛选」造成的误读。

## 2. 信息层级

### 2.1 主列表页优先级

| 优先级 | 信息 | 位置 | 理由 |
|---|---|---|---|
| P0 | 快照日期、日期口径 | A + C | 所有数字依赖这两个前提，必须先确认 |
| P0 | 批次可信度 | B | 数据不完整时，任何计数都可能被误读 |
| P0 | 包总数、命中、未命中 | D | 回答「昨天发生了什么、有多少需要关注」 |
| P1 | 分组名与组级计数 | E 组头 | 团队是默认视角；计数决定是否展开 |
| P1 | 竞品真实名称 + 图标 + 命中状态 | E 行 | 回答「是哪个 App、能不能看到详情」 |
| P1 | 未命中子区 | E 行内 | 诚实呈现，不能被命中行淹没 |
| P2 | 当前口径日期 | E 行 | 解释「为什么在今天这一批」 |
| P2 | 类目、最低 iOS、包数、截图数 | E 行 | 辅助判断，不抢占首行 |
| P2 | 近 7 天时间线 | E 组头 | 上下文趋势，不是当日任务的主信息 |
| P3 | 抓取区域、资产状态、源元数据 | 详情页 | 证据与排障用，主列表不展示 |

视觉层级（意图，不给数值）：

- 页面只有一个 H1 级标题「竞品日报」。
- 组名与组计数是列表内的第一层；竞品名称是第二层；`package_code`、日期、类目是第三层（次要文字/等宽）。
- 未命中使用独立徽标和占位图标，不只靠颜色区分；图标区域用虚线框或问号占位，命中用真实图标。
- 汇总卡的数字大于标签；「未命中」卡使用警示语义色，但旁边始终有文字。

### 2.2 详情页优先级

| 优先级 | 信息 | 位置 | 理由 |
|---|---|---|---|
| P0 | 竞品身份（图标、名称、Bundle ID） | B | 确认打开的是哪个 App |
| P0 | 快照日期与口径 | C | 所有内容属于哪一天的证据 |
| P1 | 截图缩略图 | F | 运营/管理最关心的「长什么样」 |
| P1 | 版本历史 | G | 产品/研发最关心的「当天在什么版本」 |
| P1 | 投放/上架/首百/下架日期 | E | 竞品节奏判断 |
| P2 | 类目、最低 iOS、当前版本 | E | 分类与兼容性判断 |
| P2 | 未命中原因说明 | 未命中变体 | 避免用户以为页面坏了 |
| P3 | 命中区域、价格、评分、appleId、源展示名 | E / H | 证据与追溯 |
| P3 | 图片/详情完整性警告 | F / E 内联 | 只在异常时出现，不常驻 |

详情页阅读顺序：身份 → 哪一天 → 图片 → 版本 → 事实 → 元数据。先满足「看长相、看版本」，再给证据字段。

### 2.3 状态与边界的呈现规则

- **口径切换后**：标题、日期行、每行日期标签、详情上下文条必须同步变化；不能只换列表数据而保留旧标签。
- **分组维度切换后**：组头名称与行内补充字段同步变化。按团队分组时行内不重复团队；按类目或 iOS 分组时行内显示团队，避免上下文丢失。
- **缺失值**：类目缺失进「未分类」，iOS 版本缺失进「未知 iOS 版本」，`listing_date` 为空显示「—」而不是空白。
- **多包竞品**：主列表行显示「N 个包」；详情用包切换器分离各包的快照，不做合并展示。
- **筛选计数**：状态筛选生效时，组头计数为筛选后的计数，并在列表头加一行「当前为筛选结果 · 共 X 包」；顶部汇总卡仍显示当日全量。
- **时间线**：只在组头出现，不重复放在页面顶部；7 天按所选日期倒推 6 天，始终使用当前日期口径。无批次的日期显示为空心柱，不可点击。

## 3. 交互流程

### 3.1 进入「竞品」Tab（首次加载）

```text
点击「竞品」Tab
→ 读取状态：无 URL 参数时 date=昨天(UTC)、date_kind=first_ad、group_by=team、status=all
→ 并行加载：汇总 + 分组列表 + 日期列表（用于时间线与可选日期）
→ 显示骨架（标题、控制条、4 张汇总卡、3 个组骨架）
→ 成功：
    批次正常 → 展示汇总 + 全部展开的分组
    批次不完整/过期 → 先展示提示条，再展示数据
→ 失败：见 3.9
```

焦点落在页面标题或列表头（不落到第一个可点击行，避免误触）。屏幕阅读器播报「竞品日报，2026-11-18，共 N 个包」。

### 3.2 日期选择

入口：前一天/后一天箭头、日期控件、时间线柱子、「回到昨天」。

```text
选择日期 D
→ 控件即时显示 D；列表进入骨架
→ 请求 D 的快照（保留当前 date_kind / group_by / status）
→ 有批次：刷新标题日期、批次条、汇总、分组、时间线
→ 无批次：进入「该日期无快照」态（见 4.6）
→ 未来日期：日期控件禁选，不能触发请求
→ 日期 D 不是昨天：显示「回到昨天」
```

- 切换日期后，保留仍然存在的分组的展开状态；新出现的组默认展开。
- 状态筛选保持；如果筛选后无结果，进入筛选空态而不是日期空态。
- 时间线点击与日期控件完全等价；点击当前日期的柱子不重复请求。
- 请求竞态：最后一次选择优先，前一次响应丢弃（避免慢请求覆盖新日期）。

### 3.3 日期口径切换（投放 / 上架）

```text
点击「上架日期」
→ 分段控件选中态立即切换
→ 请求同一日期的 listing 口径数据（分组、筛选保持不变）
→ 标题日期行增加/替换口径标签
→ 汇总卡、组头计数、行内日期标签、时间线全部使用新口径
→ 若 listing_date 为空的包不进入当日结果，这是预期行为；在页脚说明中提示
→ 若详情页正打开：不就地切换；返回列表后使用新口径重新进入
```

关键约束：**口径是全局状态，不是列表局部过滤**。任何可见的日期标签都必须标明口径，避免把上架日误读为投放日。

### 3.4 分组维度切换

```text
点击「类目」/「iOS 版本」
→ 请求 summary(group_by=...)
→ 分组列表替换；所有组默认展开
→ 行内补充字段变化：按团队分组时不显示团队；按类目/iOS 分组时显示团队
→ 组排序按新维度重新计算
→ 汇总卡不变（包维度总量不随分组变化）
→ 若某维度全部缺失：所有包进入「未分类 / 未知 iOS 版本」单组，不显示空列表
```

### 3.5 命中状态筛选

```text
点击「未命中」
→ 分段控件选中；列表区显示「仅看未命中 · N 包 / 当日共 M 包」
→ 只保留包含未命中包的组；组体只显示未命中子区
→ 组头计数切换为筛选后计数
→ 汇总卡保持当日全量
→ 清除筛选：点击「全部」或提示条上的「清除」
→ 无匹配：显示筛选空态（4.7B），提供「清除筛选」
```

「命中」筛选同理，只显示命中竞品行。筛选不改变日期、口径和分组。

### 3.6 下钻到竞品详情

```text
点击竞品行（整行可点击，包含图标和名称）
→ URL 增加 view=detail、competitor=<appleId 或 package_code>、package=<当前包>
→ 进入详情页：先显示身份头 + 快照上下文骨架，再加载截图/版本
→ 详情继承 date / date_kind / group_by / status
→ 点击「返回竞品日报」
→ 回到原列表，恢复滚动位置、展开状态和筛选
→ 浏览器后退键行为相同
```

- 组头点击只展开/收起，不进详情；不可把组头做成链接。
- 竞品行必须是可键盘聚焦的链接语义；Enter 进入详情。
- 详情页不自动播放轮播、不自动弹层。

### 3.7 未命中包查看

入口有三个，指向同一结果：

1. 组内「App Store 未命中」子区的行。
2. 顶部「未命中」筛选后的行。
3. 详情页内跳转。

```text
点击未命中行
→ 进入未命中详情
→ 身份头显示：占位图标、源 display_name、「App Store 未命中」徽标、package_code、团队
→ 快照事实照常显示（投放/上架/首百/下架日期）
→ 「为什么未命中」说明块：
    - 已用 package_code 作为 Bundle ID，在 8 个抓取区域精确查找
    - 未找到 bundleId 完全一致的结果
    - 这不代表包不存在，可能尚未上架或使用其他 Bundle ID
→ 不显示截图 / 版本历史，替换为「未命中，无 App Store 详情可展示」
→ 次要操作「到 App Store 搜索中查询此 Bundle ID」：切到搜索 Tab，预填 Bundle ID，不自动搜索
→ 返回列表，保持原状态
```

未命中行在列表中的优先级：组内命中行之后、独立子区；组头未命中数始终可见。不得把未命中包混入命中行中仅用小字号标注。

### 3.8 时间线的使用

- 组头的 7 根柱子代表所选日期及其前 6 天，按当前日期口径统计该组的包数。
- 悬停或键盘聚焦：显示「11-12 · 8 包」。
- 点击有批次的柱子：切换日期，保持口径、分组、筛选。
- 无批次日期：空心柱、不可点击，并在无障碍标签中说明「无快照」。
- 当前日期柱：描边高亮，不依赖颜色单独表达。

### 3.9 加载、失败与恢复

- **加载**：保留控制条可操作；列表与汇总显示结构性骨架，不显示旧的数字，避免把旧数据误认为新日期的数据。
- **请求失败**：列表区替换为错误态，显示「报告加载失败」、简短原因、`重试`；控制条仍可用，用户可改日期或口径重试。顶部保留当前日期，明确失败的是哪一次请求。
- **局部失败**：若汇总成功但分组失败，保留汇总并只让分组区显示错误与重试；不整页报错。
- **图片失败**：单张截图显示占位和「截图加载失败」；不阻断文字与版本历史。
- **批次异常**：不阻塞浏览，提示条常驻在本页数据上方。
- **竞态**：新请求发出时取消/忽略旧响应；骨架只属于最后一次请求。

### 3.10 详情页内的包切换

```text
竞品有多个包
→ 包切换器显示所有 package_code + 状态点
→ 默认选中 URL 中的 package；无参数时选第一个命中包
→ 切换包：
    更新 URL 的 package 参数
    更新当日快照事实、截图区、版本历史
    身份头（App 名称、图标）保持不变
→ 若某个包详情失败：只让该包的 E/F/G 区显示错误与重试，身份头和包切换器保持可用
```

### 3.11 键盘、无障碍与响应式

- Tab 顺序：Tab 导航 → 日期 → 口径 → 分组 → 状态 → 汇总（静态，不聚焦）→ 分组头 → 行 → 未命中子区。
- 分组头是 `button` 语义并带展开状态；竞品行是链接语义；时间线每根柱子可聚焦并带完整文本标签。
- 状态不能仅靠颜色：未命中同时有文字徽标和占位图标；当前日期柱有描边；选中分段有文字加粗/下划线。
- 加载与结果数量变化通过 `aria-live=polite` 播报，避免每个骨架都播报。
- 桌面为主（1280–1440）；窄屏时控制条纵向堆叠、汇总卡 2×2、组头计数换行、详情双栏改为单栏。移动端不承诺完整操作体验，但查看与下钻必须可用。

## 5. 与 WWA-006 验收项的对应

| 验收项 | UX 承载 |
|---|---|
| 新增「竞品」Tab | 1.1 全局头部同级 Tab |
| 默认展示昨天 | 3.1，日期控件默认昨天，最大可选昨天 |
| 投放 / 上架口径切换 | 3.3；所有日期标签随口径变化；详情继承口径 |
| 按团队 / 类目 / iOS 版本分组 | 3.4；组头、行内补充字段、缺失值分组规则 |
| 主列表展示包数、命中、未命中、近 7 天 | 2.1、3.8；组头计数与时间线 |
| 点击竞品进详情，展示全部包 / 图标 / 截图 / 版本 | 1.3、3.6、3.10；多包切换器 |
| 未命中包明确展示 | 0.3、2.3、3.7、4.3；独立子区 + 筛选 + 未命中详情 |
| 页面不重复展示同一天同包 | 聚合模型按 appleId 聚合包；未命中按 package_code 唯一 |
| 图片从本地加载 | 详情截图区使用本地路径；失败占位，不阻断 |
| 列表与详情口径一致 | 详情只读 URL 状态，不单独切换口径 |

### 未决但不阻塞设计

- 同一 App 多个包时，主列表「竞品数」按 appleId 去重，包数按包计；后端需保证 `appleId` 稳定。
- `category` / `minimum_os_version` 缺失时的「未分类 / 未知 iOS 版本」分组需要在 API 聚合层保留，否则前端无法还原组头计数。
- 图片清理策略未定；UX 已按「可能缺失」设计占位与提示。
