# UI 规范：竞品周动态（/weekly）

> 输入：`docs/tickets/weekly-report/REQUIREMENTS.md`（口径与验收基准，不在本文重开）、`docs/design/shelf-trend.md`、`docs/UI-competitor-daily.md`、`docs/design/astryx-theme.md`、`DESIGN.md`、`src/theme/wxTheme.ts`、`src/shelf/*`、`src/competitor/*`。
> 页面模式：**Operate / Read**。内部工作台，一页读完一周，先读结论，再看团队，最后看四周变化。
> 范围：页面层级、栅格、视觉 token、组件选型、卡片排版、图表几何、状态、可访问性、手机行为、复用/新建清单。
> 不包含：HTML / CSS / 组件代码；不新增设计系统；不引入图表库、图标库、字体或依赖。
> 冲突优先级：统计口径以 REQUIREMENTS 为准；颜色 / 字体 / 状态语义以 `DESIGN.md` 为准；组件几何以 Astryx 主题为准；本页页面级栅格与卡片排版以本文为准。

## 0. 设计结论（先看这九条）

1. **一页读完，不做第二个看板。** 周报不是 `/shelf` 的缩水版：不筛选、不下钻、不做包明细、不做 90 天图。四周只画 4 个槽，团队只到聚焦层。
2. **一句话先给结论。** 周头之后直接是摘要句，17px/600，数字走等宽；摘要不是 KPI 卡，不铺底、不加边框盒子。
3. **团队卡片是主角。** 6 张平涂卡片，3 / 2 / 1 列；每张牌只有一个 28px 主数字，其余信息全部退后。卡片不是表格：不列列头、不画斑马纹、不做 label-value 对齐网格。
4. **变化方向不用红绿。** 环比正负用 `+ / -`、`↑ / ↓`、`增幅 / 降幅` 表达，颜色仍是墨色；红色只留给请求失败，琥珀只留给批次不完整。
5. **四周图表比 `/shelf` 轻一档。** 固定 4 个周槽、无横向滚动（手机除外）、无筛选 chip、无点击下钻、无 grow-in 动画；三行指标共用一条图例和一条周标签。
6. **精确值始终有文本出口。** 趋势柱顶直接标数；三行指标图提供每个指标一个 collapsed 的「数值」表，屏幕阅读器另有常驻隐藏表。不依赖 hover。
7. **平涂到底。** 空气底、墨色字、1px 规线、零阴影零渐变。团队卡片使用 1px 发丝边框和 8px 圆角，是页面级「平涂卡片」例外，不引入浮卡。
8. **只在必要处用色。** 蓝色只给占比轨、当前周标记和交互；团队身份色只出现在三行指标图的柱与图例；琥珀 / 红只出现在批次质量与错误态。
9. **本页没有应用图标和截图缩略图。** 不为「看起来完整」补占位图。图标 / 截图规格见 §7.6，只定义本页实际出现的标记。

### 0.1 总指挥确认（2026-11-24）

- 团队卡片的 1px 发丝边框 + 8px 圆角是**页面级平涂例外**，不视为浮卡；仍禁止阴影与渐变。
- 团队身份色（含绿色/紫色）只用于三行指标图的柱与图例，表示身份不表示好坏；状态色语义不变。
- 三指标 72 根柱接受；精确值以折叠「数值」表 + 屏幕阅读器隐藏表兜底，不依赖 hover。
- 批次状态映射 `ok → 正常`、`partial → 部分`、`failed → 失败`、`null → —`。
- 团队已解析包 `<3` 时，计数类（`N / 52`、品类包数、IAP 有/无）照常显示，比例类显示 `—`。
- 「下一周」上限只读 API 顶层 `latestCompleteWeek`，前端不按 UTC/本地时区推算。
- 不补应用图标、截图、占位图。
- 本文线框与示例中的团队/数字为设计期数据；运行时验收以 `REQUIREMENTS.md` §7.1 的真库基线为准（2026-11-24 回填后团队变化示例为「巨风 18 → 13，-5（-27.8%）」，不再是「大容 +4」）。
- **2026-11-25 起，本页所有团队显示统一走 `teamLabel` 缩写**（LivChat → LC、巨风 → JF、大容 → DR、灵蜂 → LF、蓝麟 → LL、驰猿 → CY），卡片与关注项一致；卡片团队名与关注项用 `title` 保留完整团队名。API 值、`data-team`、URL 参数仍是完整名。线框中的完整团队名仅作设计期排版示意。

## 1. 页面定位与设计方向

### 1.1 一句话

`/weekly` 回答「这一周竞品团队发生了什么」；`/shelf` 回答「拉长时间看数据长什么样」。

### 1.2 阅读顺序

1. 我在看哪一周？（周头）
2. 整体情况如何？（摘要句 → 本周结构 → 本周值得关注）
3. 哪些团队在动？（团队卡片）
4. 过去 4 周是涨还是落、节奏如何？（新增包数 → 内购比例 → 平均版本数 → 版本与投放 → 品类 / 隐私变化）
5. 数据可信吗？（脚注）

### 1.3 设计原则

- **信息优先，装饰退后。** 不用图标、编号、彩色短线、渐变、阴影来制造层级；层级只来自字号、字重、留白、1px 规线和数字位置。
- **一个视觉主角。** 团队卡片里只有一个 28px 数字；摘要句是页面级的一句话；四周图表是辅助，不抢团队卡片。
- **数字是等宽的。** 所有数字、日期、百分比、包数走 IBM Plex Mono + tabular-nums；中文叙述走 Noto Sans SC。
- **对比靠位置和文字，不靠颜色。** 变化方向有 `+ / -` 和 `增幅 / 降幅`；团队序列有固定顺序和图例；数据不足有斜纹和「数据不足」文字。
- **克制是页面的性格。** 不为了填满 1440 列把 4 根柱拉宽；不为了「丰富」给每个品类上一种颜色。

### 1.4 明确不做

- 不做包明细、下架列表、截图、应用图标。
- 不做团队筛选、维度切换、日期选择器、任意日期区间。
- 不做只能靠 hover 才能读数的图；每张图必须有可见数值或点击提示。
- 不做 90 天趋势、季度对比、预测、LLM 摘要。
- 不做不可变快照、导出、分享图、深色模式。

## 2. 信息架构与页面层级

### 2.1 页面结构

```text
/weekly
├─ 周头
│   ├─ h1「竞品周动态」
│   ├─ 周范围（Barlow Condensed 28px）
│   ├─ 上一周 / 下一周
│   └─ 数据截至 + 批次状态
├─ h2「整体情况」
│   ├─ 本周摘要（一句话）
│   ├─ h3「本周结构」（版本数 / 内购 / 品类 / 隐私 / iOS）
│   ├─ h3「版本与投放（本周）」（三项本周数值）
│   └─ h3「本周值得关注」（最多 2 条）
├─ h2「团队情况」
│   └─ 团队卡片网格（6 张）
├─ h2「过去 4 周趋势」
│   ├─ h3「新增与结构」（新增包数 / 内购比例 / 包版本数）
│   ├─ h3「版本与投放」（整体 × 3 行指标）
│   └─ h3「品类与隐私变化」（品类 Top10 / 隐私域名 Top10）
└─ 脚注（固定数据质量句）
```

### 2.2 区块顺序与优先级

| 优先级 | 区块 | 视觉权重 | 说明 |
| --- | --- | --- | --- |
| P0 | 周头 | 高 | 先确认周 |
| P0 | 整体情况（摘要 / 本周结构 / 值得关注） | 高 | 先给全团队结论与构成 |
| P0 | 团队情况（团队卡片） | 最高 | 页面唯一的大数字群 |
| P1 | 过去 4 周趋势（新增与结构 / 版本与投放 / 品类与隐私变化） | 中 | 从本周切到走势，收束页面 |
| P3 | 脚注 | 最低 | 数据质量，始终可读 |

区块之间一律用 1px `--color-border` 通栏分隔，不用卡片包住整段。

### 2.3 路由与导航

- 顶级导航顺序：`竞品日报` → `竞品趋势` → `竞品周动态` → `App Store 搜索`。
- 路由：`/weekly`；浏览器标题：`竞品周动态 · App搜索工作台`。
- `isNavActive` 必须把 `/weekly` 从「竞品日报」的激活范围中排除，保证进入 `/weekly` 时只有「竞品周动态」高亮。
- 周参数用 URL `?week=YYYY-MM-DD` 表达（该日期所在 ISO 周的周一）；缺省时服务端返回最近一个完整且有数据的周，前端用返回的 `weekStart` 回写 URL。
- 周切换使用 `replace` 写入历史，与现有筛选一致；刷新后仍停留在所选周。

## 3. 布局与栅格

### 3.1 页面框架

沿用 `AppShell` + `wxTheme`，页面自己控制内边距（与 `wx-report` / `wx-shelf` 一致，不使用 `.wx-app-main` 的 32px 包裹层，避免双重内边距）。

| 项 | 桌面 ≥1180px | 平板 841–1179px | 手机 ≤840px | 小手机 ≤640px |
| --- | --- | --- | --- | --- |
| 内容最大宽度 | 1440px | 100% | 100% | 100% |
| 页面左右内边距 | 32px | 24px | 16px | 16px |
| 页面最小高度 | `calc(100vh - 54px)` | 同左 | 同左 | 同左 |
| 周头布局 | 左标题+周范围，右周切换+数据截至 | 上下堆叠 | 上下堆叠 | 上下堆叠 |
| 团队卡片列数 | 3 | 2 | 2 | 1 |
| 卡片间距 | 20px | 16px | 16px | 12px |
| 指标图 | 4 槽 × 120px，无滚动 | 4 槽 × 120px | 4 槽 × 96px，可横向滚动 | 4 槽 × 96px，可横向滚动 |
| 趋势图 | 4 槽 × 120px | 4 槽 × 120px | 4 槽 × 88px | 4 槽 × 80px |
| 值得关注 | 2 列 | 2 列 | 2 列（≥641） | 1 列 |

- 单列纵向文档流；团队卡片是页内唯一的卡片网格，不做多栏瀑布。
- 页面本身不得出现横向滚动；只有指标图 / 趋势图容器在窄屏溢出时内部横向滚动。
- 图表内容列：版本与投放最大 720px（44px 轴 + 4×120px 槽 + 标题余量）；近 4 周趋势最大 560px（4×120px + 余量）。两者左对齐，不把 4 个槽拉满 1376px。
- 360 / 390 / 768 / 1024 / 1440 五个宽度必须目检。

## 6. 区块规格

### 6.1 周头

```text
竞品周动态                                                     [← 上一周]  [下一周 →]
2026-11-16 ~ 2026-11-22                                      数据截至 2026-11-23 · 批次正常
──────────────────────────────────────────────────────────────────────────────────────
```

- **布局**：≥1180px 两列，左标题 + 周范围，右周切换 + 数据截至，底对齐；<1180 上下堆叠。右侧控件不换行；手机两个按钮各占一半。
- **h1**：20px / 600 / 1.2，墨色；与周范围间距 8px。
- **周范围**：Barlow Condensed 28px / 600 / 1.0，`2026-11-16 ~ 2026-11-22`，两侧各一个空格；tabular-nums；不要缩写年份。
- **周切换**：
  - 两个 `Button variant="secondary" size="sm"`，可见高度 28px；手机 32px 可见，命中区 ≥44px。
  - 文案 `← 上一周` / `下一周 →`；`aria-label` 带目标周范围，例如「查看上一周：2026-11-09 至 2026-11-15」。
  - 下一周在「最近完整周」处禁用；禁用时右侧出现 12px secondary 的 `已是最新完整周`，文字明说原因，不用 tooltip。手改 URL 进入未来周时同样禁用，但文案为 `已超过最新完整周`，不冒充最新周。
  - 最近完整周：**以 API 顶层 `latestCompleteWeek` 为准**（服务端按 Asia/Shanghai 计算，与请求周无关）；`weekStart >= latestCompleteWeek` 时禁用下一周。前端不得用 `todayUtc()` 或本地时区自行推算。
  - 切换时周范围立即更新，数据区进入骨架；不保留旧周数字。加载中禁用上一周 / 下一周，过期响应丢弃，避免快速切换的竞态。
- **数据截至**：12px 等宽 secondary，格式 `数据截至 2026-11-23 · 批次正常`。状态映射：`ok → 正常`、`partial → 部分`、`failed → 失败`、`null → —`。
- **批次提示条**：仅 `partial` / `failed` 时出现，放在周头与摘要之间。
  - `partial`：1px 左规线 `--color-border-warning`，文字 `--color-text-warning`，12px，`本批数据可能不完整，统计仅供参考。`
  - `failed`：1px 左规线 `--color-border-error`，文字 `--color-text-error`，`本批数据抓取失败，以下为已入库数据。`
  - 不加琥珀 / 红铺底，不加图标，不做弹窗。
- **周头分隔线**：1px `--color-border`，通栏。

### 6.2 本周摘要

```text
本周摘要

```

#### 6.3.9 如何避免卡片像表格

1. **只有一个大数字。** 主数字 28px，其余最大 17px（团队名）；图表值最大 11px。
2. **分布用图，不用列。** 版本 / 内购是竖柱，品类 / 隐私是横条；没有列头、没有小计、没有对齐的 label-value 网格。
3. **没有卡内横线列表。** 卡内只用两条 1px 分割线（占比轨后、版本与投放块前）；图之间靠留白和 12px 小标题分组。
4. **图表可点，卡片本身不可点。** hover 只作用于单根柱 / 单条，不整卡变色、不抬升。
5. **排名是文本 `01`，不是表格行号。** 不画表格列头「排名 / 团队 / 包数」。
6. **颜色只做强调。** 蓝阶只用于版本 / 品类 / 隐私，内购用 accent + 墨；不做彩色标签墙。

### 7.3 错误

```text
──────────────────────────────────────────────────────────────────────
周报加载失败
请求失败：HTTP 502                                      [重试]
──────────────────────────────────────────────────────────────────────
```

- 周头保留；错误块在周头与脚注之间，顶部 1px `--color-border`，上下 30 / 36px 留白，最大宽度 760px。
- 标题 17 / 600 `--color-text-error`；原因 12px 等宽 secondary；动作按钮 `Button variant="secondary" size="sm"`：常规错误为「重试」，400 为「回到最近一周」。
- 错误映射：
  - 400：`周参数无效` + `请选择一个完整的 ISO 周。`（不显示原始英文错误）；不显示「重试」，因为重复无效参数只会再次失败；动作改为「回到最近一周」，清除 `?week=` 后重新取默认周。
  - 503：`周报服务暂不可用` + `服务端未配置数据库或暂不可用。`
  - 500 / 网络：`周报加载失败` + 可读原因；生产环境不显示堆栈。
- 不使用红色铺底、不使用琥珀、不使用 alert 弹窗，不把失败做成团队卡状态。
- 重试重取当前 `?week=`；周切换保持可用，允许用户换一周。

### 7.4 该周无已解析包

```text
──────────────────────────────────────────────────────────────────────
该周没有已解析入库包
本周入库 7 个包，但都没有命中 App Store，未计入统计。      [查看上一周]
──────────────────────────────────────────────────────────────────────
```

- 使用 `EmptyState`：无卡底、无阴影；标题 17 / 600；说明 13px secondary；动作 `Button variant="secondary" size="sm"`。
- 保留周头、周切换和脚注；不渲染摘要、团队卡、指标、结构、趋势、关注项。摘要默认隐藏；如产品要求保留，只保留一句 `该周新增 0 个包`，不显示环比负值。
- 说明按 `ingestedPackages` 分支：
  - >0：`本周入库 N 个包，但都没有命中 App Store，未计入统计。`
  - 0：`本周没有入库包。`
- 动作「查看上一周」跳到 `weekStart - 7`；如果上一周也为空，继续显示空态，不自动跳过。
- 不显示 0 张卡、0 根柱、空坐标轴、空表头。
- 脚注按固定句展示总数 / 未解析 / 数据截至 / 批次状态。

### 7.5 部分数据不足

- 团队 <3 包：团队内比例字段 `—`，见 §6.3.8；不把整页降级。
- 指标某周为空：不补 0，柱位留空。
- `投放→下架` 的 0：是真实值，画零线短柱，提示带 `已下架 n/m`；不要与「无数据」混淆。
- 趋势 0 周：斜纹 + `数据不足`，不画 0 柱。
- 批次 partial / failed：顶部提示条 + 脚注；数据照常展示，不阻塞阅读。
- 所有 `—` 是文本，不是空白；不能用颜色或空白单独表达缺失。

## 8. 可访问性与手机行为

### 8.1 语义与结构

- 一个可见 h1「竞品周动态」；每个区块一个 h2（14px / 600），通过 `aria-labelledby` 与 section 关联。
- 团队卡片用 `<ul>` / `<li>` + `<article>`；团队名是 h3。排名 `01` `aria-hidden`，另给 `visually-hidden` 的「第 N 名」。
- 摘要是一个 `<p>`，不是标题；eyebrow `本周摘要` 是普通文本。
- Top10 行用 CSS grid；迷你柱每格是 `<button>`，`aria-label` 含名称、周与占比。
- 脚注是 `<footer>` 内的 `<p>`，不是 `<small>`。

### 8.2 图表

- 每张图：`<figure>` + 可见区块 h2 / h3；绘制层 `role="img"` + 简短 `aria-label`；柱、段、轴线全部 `aria-hidden="true"`。
- 三行指标图共用一条周标签；比例柱与 Top10 迷你柱的每个可交互格都有 `aria-label` 周值。
- 趋势图：数值和周标签本身就是可见文本，不需要隐藏表；`aria-label` 用一句话复述 4 周数值。
- 结构图：每根柱 / 每条横条是 button，带名称 + 包数 + 百分比的 aria-label；不做 72 个装饰性 tab stop。
- 不做 72 个 tab stop；`数值` 按钮是唯一的展开控件。点击图表只显示数值提示，不跳转。
- 指标图在窄屏溢出时，滚动容器 `tabindex="0"` + `aria-label="指标图横向滚动区域"` + 2px 蓝焦点环。

### 8.3 键盘与焦点

- Tab 顺序：跳过链接（AppShell 自带）→ 主导航 → 上一周 → 下一周 → 各指标「数值」按钮 → 空态 / 错误动作 → 脚注。
- 所有可交互元素 `:focus-visible` 2px 风暴蓝、offset 2px；不允许 `outline:none` 无替代。
- `数值` 按钮：可键盘展开 / 收起，`aria-expanded` 同步；展开后表内不接受 tab 焦点（静态表）。
- 周切换按钮：Enter / Space 触发；禁用时不可聚焦或 `aria-disabled="true"`，并在旁边有文字说明。
- 焦点环不能落在墨底内部失去对比；需要时用 offset 让环落在空气底上。

| `trends.metrics[].overall[]` | 整体指标图 | 每周一根柱，直接展示全体包聚合值；点击提示 `整体：N 天` |
| `trends.iapShare[]` | 内购比例 4 周柱 | `share` 直接当百分比；柱高按 0..100%；无点留空 |

| `trends.categoryWeeks[]` / `trends.privacyWeeks[]` | 品类 / 隐私域名 Top10 变化 | 本周桶排除 unknown、按 `share` 降序取前 10；基准周取数组首项（有已解析的最早周）；缺失桶按 0 计 Δ |
| `highlights[]` | 本周值得关注 | 最多 2 条；`team_change` 在前，`category_change` 在后 |

**格式化约定**

- 计数：整数，千位不加逗号（工作台数据量小；如需可后续统一）。
- 百分比：API 0..1 → `(x * 100).toFixed(1) + "%"`。
- 百分点：`deltaPp` 已经是百分点数值 → `toFixed(1) + "pp"`，不要再乘 100。
- 天数：`toFixed(1)`，去掉末尾 `.0`；负值保留 `-`。
- 日期：统一 `YYYY-MM-DD`；摘要内可用 `11-22` 短格式，但必须带年份在周范围处。
- 空值：`—`，不用 `N/A`、`null`、`0` 代替。

### 10.3 明确不新建

## 11. 风险与待确认

| 级别 | 风险 / 待确认 | 说明 | 建议 |
| --- | --- | --- | --- |

| 中 | Top10 两栏 × 10 行信息量较大 | 每行四列已压缩；占比与 Δpp 必须等宽 | 用真实 2026-11-16 周数据目检；若挤，优先隐藏迷你柱保留 Δpp |
| 中 | Δpp 基准不是固定「4 周前」 | 最早一周常为空，故用窗口内最早有数据周 | 列头写明 `较 MM-DD`；空窗口显示 `—` |
| 中 | <3 包规则的解释 | 本文默认：`N / 52` 保留，团队内比例 `—`；计数保留 | 与产品确认「比例类字段」是否包含 `N / 52`；如包含，改为 `—` 并隐藏占比轨 |

## 12. 视觉验收清单

- [ ] `/weekly` 可访问；导航顺序为 竞品日报 → 竞品趋势 → 竞品周动态 → App Store 搜索；进入 `/weekly` 时「竞品周动态」高亮、「竞品日报」不高亮。
- [ ] 浏览器标题为 `竞品周动态 · App搜索工作台`。
- [ ] 默认打开最近一个完整且有数据的 ISO 周；URL 回写 `?week=YYYY-MM-DD`；刷新保持。
- [ ] 上一周 / 下一周切换正确；下一周在最近完整周处禁用，并有 `已是最新完整周` 文字；未来周显示 `已超过最新完整周`。
- [ ] 周范围使用 `YYYY-MM-DD ~ YYYY-MM-DD`，Barlow 28px；不缩写年份。
- [ ] 摘要句使用新增入库包数（含未解析）：`新增 112 个包 … 环比 -7（-5.9%）`；上周入库 0 用 `环比新增 N 个包`；数字等宽。
- [ ] 团队卡片按 API 顺序（包数降序、团队名升序）排列；6 张卡；≥1180 3 列、641–1179 2 列、≤640 单列。
- [ ] 卡片主数字 28px 等宽，是卡内最大数字；团队名 17px；环比 14px；排名 12px。
- [ ] 卡片不是表格：无列头、无斑马纹、无 label-value 对齐网格、无行内 hover、无行内操作。
