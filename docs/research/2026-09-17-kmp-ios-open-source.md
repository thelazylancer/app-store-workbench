# KMP 开源 iOS 项目研究草稿

> 截止日：2026-09-17（Asia/Shanghai）
> 范围：Kotlin Multiplatform（KMP）及 Compose Multiplatform（CMP）生态中，能直接帮助 iOS 开发的开源 App、官方示例和常用组件。
> 来源口径：只引用项目官方 GitHub 仓库、仓库内源码/README、官方文档和官方 Release；社区项目的仓库本身视为一手实现来源，不用二手文章替代证据。

## 结论先行

- 新项目先看官方模板：需要原生 SwiftUI 时看 [KMP-App-Template-Native](https://github.com/Kotlin/KMP-App-Template-Native)；需要共享 UI 时看 [KMP-App-Template](https://github.com/Kotlin/KMP-App-Template) 和 [Compose Multiplatform examples](https://github.com/JetBrains/compose-multiplatform/tree/master/examples)。
- 要参考真实业务结构，优先 [KMP production sample](https://github.com/Kotlin/kmp-production-sample)、[Fruitties](https://github.com/android/kotlin-multiplatform-samples/tree/main/Fruitties)、[KaMPKit](https://github.com/touchlab/KaMPKit)、[KotlinConf App](https://github.com/JetBrains/kotlinconf-app) 和 [Confetti](https://github.com/joreilly/Confetti)。`KMP production sample`、`Fruitties` 适合看官方/平台方的架构取舍；`KaMPKit`、`KotlinConf App`、`Confetti` 更适合看多模块和产品化接线。
- 原生 UI 路线的关键不是“能否编译出 framework”，而是 Flow、挂起函数、ViewModel 和资源如何形成 Swift 可用 API；可重点对照 [KMP-NativeCoroutines](https://github.com/rickclephas/KMP-NativeCoroutines)、[KMP-ObservableViewModel](https://github.com/rickclephas/KMP-ObservableViewModel) 和 [SKIE](https://github.com/touchlab/SKIE)。
- 维护状态不能只看 README 示例版本：下表同时记录 Release 页面和默认分支提交快照。`D-KMP-sample` 明确写明“不再更新”，只保留作历史对照；`Fruitties` 仍是有效官方参考，但默认分支最近提交较早。

## 口径

- “iOS target”指仓库/组件明确有 `iosArm64`、`iosSimulatorArm64` 等 Kotlin/Native target，或有可运行的 iOS 工程。
- “Swift 集成”中：`✓` 表示仓库或官方文档展示了 Swift/SwiftUI/UIKit/Swift Package 的直接接线；`△` 表示可以通过 KMP framework 使用，但项目没有额外的 Swift-facing API；`—` 表示不是运行时 iOS 组件，或不以 Swift API 为目标。
- “最近提交”链接到官方 GitHub 默认分支提交页；日期是 2026-09-17 核对时看到的最新提交日期（UTC），页面之后可能继续变化。

## 选型提示

1. **原生 SwiftUI**：以 `KMP-App-Template-Native` 或 `kmp-production-sample` 为起点，再按需要加入 NativeCoroutines、ObservableViewModel、SQLDelight 和 Koin。
2. **共享 CMP UI**：以 `KMP-App-Template` 和 CMP examples 为最小基线；KotlinConf App、Confetti、Alkaa 可继续参考真实产品、多模块和发布工程。
3. **已有 Android 应用迁移**：先读 `kmp-integration-sample` 的 `final` 分支；需要更大规模模块化时再对照 `nowinandroid-kmp`，但要区分社区移植和 Google 官方实现。
4. **版本判断**：以各项目 Release 页面和兼容矩阵为准。部分 README/文档会滞后于最新 Release；尤其要注意 Compose、Ktor、SKIE、moko-resources、Decompose 的预览版或 beta 线。

本稿只新增研究文档，没有修改应用代码。
