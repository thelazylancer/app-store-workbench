## 0. 设计结论（先看这六条）

1. **一列到底，不做卡片墙。** 页头筛选 → 每周柱状图 → 分布堆叠图 → 临时明细表，全部落在既有 1440px 内容列里，用 1px 规线分段，不用面板、阴影、圆角容器。
2. **周是分类轴，不是时间轴。** 只画有数据的周；本周未完整也照常画；不补零、不留空槽、不标注。相邻两根柱子可以跨越多周，用户靠周标签识别。
3. **总数量用墨，分布用蓝阶。** 周总量柱 = 墨 55%（延续 DESIGN 的「普通柱 0.55」）；分布已知桶 = 蓝色阶；「其他」= 墨 32%；「未知」= `--color-track`。全页不出现琥珀 / 绿 / 红，错误态除外。
4. **数值始终可见。** 柱顶数值、图例计数、表内数据都在页面里；不依赖 hover tooltip，不做百分比堆叠。
5. **明细表是核对工具，不是数据网格。** 平铺、无图标、无斑马纹、无行内操作；窄屏降级为堆叠行；未解析包只显示 Bundle ID + 未知。
6. **本页没有图标和截图。** 公开 API 白名单不返回图标 / 截图字段；不要为了「看起来完整」补占位图、应用图标或截图缩略图。

## 1. 信息架构

### 1.1 页面层级

```text
/shelf
├─ 页头
│   ├─ h1「竞品入库趋势」
│   ├─ 统计范围 + 总包数（12px，数据走等宽）
│   └─ 团队筛选（全局，默认「全部」，写入 ?team=）
├─ 数据区
│   ├─ 每周入库包数        单系列柱状图，按入库周
│   ├─ 入库包分布          数量堆叠图 + 维度切换（类目 / 最低 iOS / 内购）+ 图例
│   └─ 图表下钻            点击柱 / 柱段弹出明细（按类目分组）
```

层级规则：

- **团队筛选是全局的**，同时作用于两张图和明细表。
- **维度切换是局部的**，只作用于「入库包分布」，放在该图区块标题右侧，不放进页面顶部工具栏。
- 明细表不受维度切换影响。
- 不做筛选结果统计卡、不做概览指标宫格；总量只出现在页头 meta 行与图例/柱顶数值里。页头不单独显示「未知数」：未知数随维度变化（类目 / iOS / 内购的 unknown 口径不同），只应出现在当前分布图的图例里，避免一个数字被读成全局未解析数。

### 1.2 路由与导航

顶部导航顺序：`竞品日报` → `竞品趋势` → `App Store 搜索`。

| 路径 | 高亮导航项 | 说明 |
| --- | --- | --- |
| `/` | 竞品日报 | 仅首页 |
| `/package/:code` | 竞品日报 | 详情属于竞品半区 |
| `/shelf` | 竞品趋势 | 新页面 |
| `/search` | App Store 搜索 | 搜索页 |

必须修正现有 `isNavActive`：当前 `to === "/"` 只要不是 `/search` 就返回真，访问 `/shelf` 时「竞品日报」会错误高亮。验收时明确断言：

- `/` 只匹配 `/` 和 `/package/*`。
- `/shelf` 只匹配 `/shelf`。
- 浏览器标题：`竞品趋势 · App搜索工作台`。
- URL 只使用 `?team=`；空值或缺省 = 全部。切换团队用 `replace` 写入历史，避免每次下拉都污染后退栈。

### 1.3 数据边界与计数前提

- `GET /api/public/shelf/trend` 同时驱动两张图；`GET /api/public/shelf/packages` 驱动明细表。
- 两张图必须来自同一份 `trend` 响应、同一组周桶、同一个 `packageCount` 口径；不要把柱状图与堆叠图分别请求后各自取数。
- 计数按包，不按 `appleId` 去重；未解析包仍计入周总量，并进入「未知」桶。
- 周分桶由后端 / 共享工具统一完成（周一至周日）；前端不得用本地时区重新切周。明细表的「入库周」必须与图表周标签逐字一致。
- 「按最新版本上架时间」图与「每周入库包数」同区块、共用团队筛选；它只统计已上架的包（能拿到版本发布时间），周桶按每个包最新一次版本的上架时间切分，所以两图的总包数可以不同，并在图旁注明「限已上架包」及参与统计的包数。
- 页脚不放说明性文案。

已定稿的共享契约见 `shared/shelfTypes.ts`；本设计以它为准：

- `ShelfPackageRow`：`packageCode`、`name`（仅命中包，App Store 名称）、`team`、`targetDate`、`weekStart`、`category`、`minimumOsVersion`、`appVersion`、`iap`（`yes / no / unknown`）、`listingDate`、`offlineDate`、`resolved`。
- `ShelfPackagesResponse`：`total`（过滤后总行数）、`limit`（默认 200、上限 500）、`rows`（按 `targetDate` 升序、`packageCode` 升序）。
- `ShelfTrendResponse`：`weeks`（只含有数据周，`weekStart` 升序）、`releaseWeeks`（同一批包按「最新版本上架时间」重新分周，只含能拿到版本发布时间的包）、`totals`、`teams`（全量、不受团队过滤影响）、回显 `from / to / team / groupBy`。

不得返回或展示：`first_ad_date`、源 `display_name`、`lookupStatus / enrichStatus / assetStatus` 原值、原始 `appStoreJson`、batch / sync / stale。`listingDate` / `offlineDate` 是上架 / 下架日期，不是投放日期；未解析包也可能有这两个值（源数据提供），可正常展示用于核对。**任何情况下都不得用投放日期顶替上架 / 下架日期。**

明细表可能被 `limit` 截断（当前 93 行 < 200，不触发）：必须用 `total` 显示总数；`rows.length < total` 时显示「共 N 行 · 显示前 M 行」，不静默丢行、不做分页。

## 2. 布局与栅格

### 2.1 页面框架

沿用 `AppShell` + 1440px 内容列；不使用 `wx-app-main` 的 32px 包裹层，页面自己控制内边距（与 `wx-report` / `wx-detail` 一致）。

| 项 | 桌面 ≥1180px | 平板 841–1179px | 手机 ≤840px | 小手机 ≤640px |
| --- | --- | --- | --- | --- |
| 内容最大宽度 | 1440px | 100% | 100% | 100% |
| 页面左右内边距 | 32px | 24px | 16px | 16px |
| 页头布局 | h1 左、团队筛选右，底对齐 | 上下堆叠 | 上下堆叠 | 上下堆叠 |
| 图表块高度 | 240px | 200px | 176px | 176px |
| 图表周槽宽度 | 88–120px | 88–120px | 88–120px | 88–120px |
| 明细表形态 | ≥1280px 表格；1180–1279 堆叠行 | 堆叠行 | 堆叠行 | 堆叠行 |

- 全局 `min-height: calc(100vh - 54px)`。
- 图表容器在周数多时内部横向滚动；表格一律不横向滚动（<1280px 降级为堆叠行）。页面本身不得出现横向滚动；360 / 768 / 1024 / 1440 全部验证。
- 单列纵向文档流；不做两图并排、不做多栏瀑布。


## 4. 图表规范

### 4.1 两图共用几何

- **同一周槽**：两张图的周槽、基线、周标签位置完全对齐，方便上下对照。
- **同一比例**：两图共用 0 → `max(每周 packageCount)` 的纵轴；分布堆叠柱的总高必须等于同一周的周总量柱高。不画 y 轴刻度，数值靠柱顶标签与图例。
- **周序**：从左到右按时间升序（最旧在左，最新在右）。
- **槽宽**：每槽 88–120px；首选 120px，最多 120px；柱宽 72px（≤840 为 64px），居中于槽内。只有 2 周时仍然只占 2 个槽，左对齐，不把柱拉宽铺满。
- **基线**：1px `--color-border`，横跨图表绘制区；无纵向网格线、无 y 轴线、无刻度。

### 6.3 错误

```text

──────────────────────────────────────────────────────────────
```

- 区块顶部 1px 规线；标题 17/600，使用 `--color-text-error`；原因 12px 等宽 secondary；重试按钮 secondary / 28px。
- 不使用红色铺底、不使用琥珀、不使用 alert 弹窗。
- 400（参数非法：`from / to / group_by / limit` 或超长 `team`）：文案「筛选参数无效」+ 简短说明；不要显示原始英文错误，也不要把 400 当作「团队无数据」。团队不存在不是错误：接口返回 200 + 空 `weeks`，走 6.5。
- 503（`Shelf data is unavailable`）：文案「趋势服务暂不可用」+ 说明「服务端未配置数据库」；重试。
- 500：文案「趋势数据加载失败」+ 可读原因；开发环境可附 HTTP 状态，生产环境不暴露堆栈。
- 失败时保留页头筛选。v1 首屏 / 团队取数不做部分成功：trend 与 packages 任一失败，用一个错误块替换两张图 + 明细表，重试并行重取两者（与 FE-2 票据一致，避免两套状态机）。
- 只有「分布维度切换」是例外：此时周总量图与明细表已经有成功数据，失败只在分布区块内显示错误 + 重试当前维度，不清空整页。

### 6.4 全局空数据

```text
──────────────────────────────────────────────────────────────
还没有入库数据
所选时间范围内没有可展示的入库包。                [重试]
──────────────────────────────────────────────────────────────
```

- 使用 Astryx `EmptyState`：无卡底、无阴影；标题 17/600；说明 13/secondary；动作 16px 间距。
- 不渲染空坐标轴、不渲染空表头、不显示 0 柱。

### 6.5 团队筛选后为空

```text
该团队没有入库数据
「团队甲」在所选时间范围内没有入库包。       [查看全部团队]
```

- 保留页头与团队下拉，选中项仍是该团队，便于用户理解发生了什么。
- 两张图和明细表都不渲染；一个空态覆盖整个数据区，不重复三次。
- 「查看全部团队」清除 URL 的 `team` 参数并重新请求。
- 若 `?team=` 的值不在接口返回的 `teams` 里，不静默回退到「全部」；保留该选项并标注「（无数据）」，同时显示上述空态。接口对不存在的团队返回 200 + 空 `weeks`，不是 400。

### 6.6 明细表单独为空

- 图表正常、packages 返回空：在表格区域显示 80px 高的紧凑空态：`没有可核对的明细。` + ghost「重试」。
- 不把整页降级为空态。

## 7. 交互与可访问性

### 7.1 团队筛选

- 标签：可见 `团队`；控件 `aria-label="团队筛选"`；选项「全部」为首项。
- 选项来源：`trend.teams`，按中文 locale 排序；当前选中值即使不在列表中也保留。
- 默认「全部」；选择团队后 URL 变 `?team=<encodeURIComponent(team)>`；选择「全部」删除参数。
- 影响：两张图 + 明细表；切换时三块同时进入加载，返回后一次性更新。
- 键盘：原生 `Selector` 行为；打开、上下移动、Enter / Space 选择、Esc 关闭；焦点环 2px 蓝、offset 2px。
- 更新后通过礼貌级 live region 播报：`已筛选团队：团队甲，共 51 包`；不要播报整张图。

### 7.2 维度切换

- 三项：`类目` / `最低 iOS` / `内购`；`aria-label="分布维度"`；单选语义。
- 默认「类目」；不写入 URL（BRIEF 只要求 `?team=`），切团队时保持当前维度。
- 切换后只重绘分布图；周总量图和明细表保持。
- 键盘：方向键切换、Home / End 到首尾；焦点环与选中态同时可见。
- 切换成功后 live region 播报：`分布维度：最低 iOS`。

### 7.3 键盘与焦点

- 页面 tab 顺序：跳过链接（AppShell 自带）→ 主导航 → 团队筛选 → 维度切换 → 重试按钮（仅错误时）→ 页脚。
- 图表本身不是 tab stop；只有可滚动的图表容器在溢出时 `tabindex="0"`，并有 `aria-label="图表横向滚动区域"`。
- 表格是静态的：没有行链接、没有行内按钮、没有嵌套 tab stop。
- 不允许 `outline: none` 且无替代焦点样式；焦环不能落在墨底内部失去对比。
- 200% 缩放：表格自动进入堆叠行；图表横向滚动；不裁切文字。

### 7.4 屏幕阅读器

- 每个区块：`section` + `aria-labelledby` 指向 h2。
- 图表容器 `role="img"` + 简短摘要；完整数据在隐藏 `<table>`。
- 表格：`<caption class="visually-hidden">核对明细（临时），按入库日期升序</caption>`；列头 `scope="col"`；应用名 `scope="row"`；未解析行行头可读为「未知，com.example.foo」；上架 / 下架日期的列头必须完整读作「上架日期」「下架日期」，不能只读「上架」「下架」。
- 状态不能只靠颜色：徽章有「命中 / 未知」文字；图例有名称和计数。
- 加载 / 错误 / 空态都有可读的标题与说明；错误原因不依赖红色单独传达。

### 7.5 动效

- 本页零动效：柱子不做入场、图例不淡入、切换维度不滑动、行悬停只换底色。
- 骨架在 `prefers-reduced-motion: reduce` 下静止；正常模式可保留 Astryx 默认的轻微脉冲，不新增自定义动画。
- 不做数字滚动、不做柱形增长、不做图表切换过渡。

## 8. 明确不要做的视觉捷径

- 不要加卡片阴影墙、白色面板、圆角容器；分区只靠 1px 规线。

- 不要用 hover tooltip 作为唯一读数方式；数值必须在页面里。
- 不要给图表加入场动画、数字滚动、柱形生长。
- 不要引入图表库、canvas 或新依赖；CSS / SVG 足够。
- 不要在明细表里显示应用图标、截图缩略图、投放日期、源展示名。
- 不要给表格加斑马纹、行选择、导出、列显隐、分页或复杂排序控件。

## 10. 交付与实现提示

- 文件边界按 `docs/tickets/shelf-trend/DESIGN.md` §5：`src/shelf/App.tsx`、`Charts.tsx`、`PackageTable.tsx`、`buckets.ts`、`filters.ts`、`states.tsx`、`styles/shelf.css`、`src/lib/shelfApi.ts`；每个文件 ≤500 行，CSS ≤300 行。
- 复用 `useDocumentTitle`；团队参数用单独的 `filters.ts` hook，只读写 `?team=`，不要继承竞品页的 `date / category / status` 参数。
- 周切分由后端 `date_trunc('week', target_date)` 完成；前端直接使用 `trend.weeks` 的 `weekStart / weekEnd` 与明细行的 `weekStart`，不本地重新切周。明细表的 `weekEnd` 优先从同 `weekStart` 的 trend 周映射取；取不到时再按 `weekStart + 6` 补齐。禁止用 `new Date()` 的本地时区推算周一。
- 类目中文映射是前端静态表，不是色板；覆盖 App Store 常见 primary genre（如 Games→游戏、Utilities→工具、Productivity→效率、Social Networking→社交、Entertainment→娱乐、Photo & Video→摄影与录像、Lifestyle→生活、Shopping→购物、Finance→财务、Education→教育、Health & Fitness→健康健美、Business→商务、Travel→旅行、Food & Drink→美食佳饮），缺映射回退英文原值。
- API 返回原始类目 key（已定稿）：前端用 `totals.groups` 按筛选范围内总数取 Top 6（并列时按 key 中文 locale 升序），其余归「其他」；每周用同一 Top 6 集合折叠，不逐周重选。图例顺序必须与段顺序一致。
- 最容易做错的三个点：
  1. 把无数据周补成空槽，导致柱子在时间轴上「漂移」；本页是分类轴，禁止补零。
  2. 图表周标签和表格「入库周」用了两套来源（一个用 `trend.weeks.weekEnd`，一个手算 / 用本地时区），导致数字对不上或周末差一天。
  3. 分布图做成百分比堆叠，或把「未知」涂成琥珀 / 红色；两者都违背已确认口径。
- 另外两个高频错误：把 `firstAdDate` 混进上架 / 下架列；以及 `<1280px` 直接隐藏表格列而不是降级为堆叠行，导致核对信息丢失。
